# 交互式数据分析工作台

离线版交互式数据分析工具，涵盖多源接入、查询分析、可视化图表、报告生成、异常检测与数据服务编排，所有分析配置与结果持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `interactive-analytics-lab:entries` 这一项，或调用 `resetModule(模块)`。
  分析流水线的运行记录存在 `interactive-analytics-lab:pipeline-runtime`，重置该模块时会一起回到示例批次。

## 分析流水线状态机

流水线节点行只保存「当前状态」，执行明细（批次、版本、尝试次数、失败区间、供数快照）全部落在运行记录里：

- 状态只能单向推进：`草稿 → 待调度 → 运行中 → 已完成（归档后）`；`运行中 → 已失败` 后只能重试，
  不能回退到待调度。未执行过的节点不允许归档。
- 依赖上游必须全部「已完成」；输出目标不可写（`readonly://`、路径含 `ro` 等）会在节点开始前拒绝，
  不会产生执行记录。按钮可见时也会在「阻塞条件」列列出具体原因。
- 中止/失败会产生一条失败区间，绑定当次 `executionId`、`batchId`、`attempt`、`version` 和本次供数，
  永久保留；重新运行会生成新的批次（波次 +1）与执行，不会清空或覆盖旧区间。
- 已归档结果再次运行会生成新版本（`v2`、`attempt` 从 1 重新计）。
- 调度工作台的重试只处理该批次里未完成的节点，已完成节点保持原波次不动，并在回执里注明跳过原因。
- 流水线与调度工作台的写操作都走 `frontend/src/api/pipeline-service.ts`：同一次点击可多选节点批量提交，
  返回逐条回执（成功 / 批内失败 / 跳过），同一节点的归档在途请求只允许一次成功。
